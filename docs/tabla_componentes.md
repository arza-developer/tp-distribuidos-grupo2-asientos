# 📋 Tabla de Interpretación del Diagrama de Arquitectura
**Cátedra:** Programación IV / Sistemas Distribuidos - UTN FRBA  
**Producto:** Sistema de Reserva de Asientos - Grupo 2  

| Componente                              | Rol                                        | Justifique la participación en el sistema                                                                                                                                 |
|:----------------------------------------|:-------------------------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Public IP Addresses**                 | Punto de Entrada / Cliente Externo         | Representa a los usuarios externos (navegadores/clientes HTTP) que consumen el sistema desde redes públicas sin acceso directo a la red interna.                          |
| **Availability Site**                   | API Pública / Fachada (Clean Architecture) | Expone el catálogo de asientos y recibe solicitudes de reserva. Desacopla la recepción del procesamiento pesado respondiendo `202 Accepted` de forma asíncrona.           |
| **SQL Database (Availability)**         | Almacén de Estado Local (Catálogo)         | Almacena los eventos y la disposición física de los asientos. Garantiza el aislamiento de datos (*Database-per-Service*).                                                 |
| **Message Broker (RabbitMQ / Azure)**   | Middleware de Integración Asíncrona        | Buffer de mensajes que desacopla temporalmente Availability de Booking. Provee resiliencia, balanceo de carga entre réplicas y absorbe picos de tráfico.                  |
| **Booking REST API**                    | Procesamiento Central (N-Layer)            | Núcleo transaccional de reservas. Gestiona la máquina de estados (`Retenida`, `Confirmada`, `Rechazada`, `Vencida`), resuelve condiciones de carrera y orquesta el cobro. |
| **SQL Database (Booking)**              | Almacén Transaccional de Reservas          | Persiste el estado de las reservas y asegura la exclusión mutua para que un mismo asiento no se reserve dos veces.                                                        |
| **Payment gRPC API**                    | Pasarela de Pagos (gRPC Server)            | Procesa transacciones financieras. Expone un contrato estricto binario de alto rendimiento vía HTTP/2 y Protobuf con endpoints para simular caídas.                       |
| **SQL Database (Payment)**              | Libro Mayor Contable (Ledger)              | Registra el histórico inmutable de transacciones de pago, cobros exitosos y motivos de rechazo financiero.                                                                |
| **Authorization Server**                | Proveedor de Identidad (IdP / OAuth2)      | Centraliza la seguridad emitiendo tokens JWT tanto para usuarios finales como para la autenticación servicio a servicio (M2M / Client Credentials).                       |
| **3rd Party Identity Providers**        | Federación de Identidad Externa            | Simula proveedores externos (Google/GitHub) que delegan la autenticación de usuarios al Authorization Server institucional.                                               |
| **Notification Service (Agregado 3.h)** | Consumidor de Eventos (Event Consumer)     | Servicio autónomo que escucha eventos de reservas confirmadas desde el Broker e informa al usuario de manera asíncrona (Eventual Consistency).                            |
